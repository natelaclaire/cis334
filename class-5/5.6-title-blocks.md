# 5.6 Title blocks and repeated content

Our two page titles are fixed presentation text. They can live in the child templates instead of being passed from PHP. Runtime data, such as the products in 5.2, still belongs in the render context.

## Replace the title variable

In `templates/tutorials/class5/base.html.twig`, replace the title element with:

```twig
<title>Campus Club: {% block pageTitle %}Welcome{% endblock %}</title>
```

Replace the h1 element in the same file with:

```twig
<h1>{{ block('pageTitle') }}</h1>
```

Declare a block once in a template. The block function renders its effective contents again, so a child's title appears in both places. Declaring another pageTitle block in the h1 would be an error. The default Welcome would be used by a child that did not override this block.

In `home.html.twig`, add the following immediately after extends, before the main block:

```twig
{% block pageTitle %}Home{% endblock %}
```

In `contact.html.twig`, add:

```twig
{% block pageTitle %}Contact{% endblock %}
```

## Stop passing fixed titles

Replace only home() and contact() in `src/Tutorials/Class5/Application.php` with these methods. Keep run(), the constructor, and all other declarations from 5.3.

```php
private function home(): void
{
    $template = 'home.html.twig';
    $args = [];
    echo $this->twig->render($template, $args);
}

private function contact(): void
{
    $template = 'contact.html.twig';
    $args = [];
    echo $this->twig->render($template, $args);
}
```

Make all template edits before reloading with the empty context. Otherwise strict variables will correctly complain about the old pageTitle expression. The unused header partial still expects that variable, but our inherited pages no longer render it.

## Verify and discuss

Both routes should look unchanged. Change the contact title block to “Reach the club”; the browser tab and h1 should both change. Restore Contact.

Reference: [Twig block function](https://twig.symfony.com/doc/3.x/functions/block.html).
