# 7.9 Class 7 reinforcement exercises

Build a browser-based **Campus Supply Quote** application with Twig views and JSON-file persistence. Choose your own supply names and presentation. These five exercises build one cumulative application: enter a product and price, validate them, save a quote, and view saved quotes later. Saving a quote does not make a purchase or send an order.

Keep the existing student repository, composer.json, composer.lock, App PSR-4 mapping, and pre-installed Twig. Do not create another Composer project or install packages. All paths below are relative to the student repository root:

```text
public/exercises/class7/index.php
src/Exercises/Class7/                      namespace App\Exercises\Class7
templates/exercises/class7/                outside public/
```

Also create `storage/exercises/class7/quotes/` with your editor or file manager. Keep templates and storage outside public/. The PHP web process must be able to write inside that storage directory. The final application uses one server-generated .json filename per quote; a submitted name or query-string path must never become a filename.

The entry loads `__DIR__ . '/../../../vendor/autoload.php'`. A controller directly in src/Exercises/Class7/ loads templates from `__DIR__ . '/../../../templates/exercises/class7'`. Its storage path is `__DIR__ . '/../../../storage/exercises/class7/quotes'`. Use strict types, typed members and returns, four-space indentation, matching filenames, and no closing PHP tag. Twig must enable HTML autoescaping and strict variables. Keep form actions and links relative to the current index.php.

Use the existing course web server with public/ as its document root. Open `/exercises/class7/index.php` at its usual host and port, normally `http://localhost:8000/exercises/class7/index.php`. All tests happen through the browser and editor.

The supplied boilerplate can be copied and adapted. These are cumulative tasks: retain previous files unless directed to replace them. A preview in Exercise 7-2 becomes a save operation in 7-3. One file per quote avoids a shared read/modify/write collection in this lesson; repeating a successful submission creates another record, not an automatic update.

## Exercise 7-2: Validate and handle custom exceptions in the browser

Create Product.php with private string name and float price properties, public getters/setters, and a constructor that uses the setters. Create EmptyNameException and ExcessivePriceException extending InvalidArgumentException. Empty class bodies and inherited constructors are sufficient.

Implement these model rules before assigning each property:

- Trim names; throw EmptyNameException for a blank or whitespace-only name.
- Throw InvalidArgumentException for negative or non-finite prices. Zero is allowed; use is_finite to reject NAN and INF as well as huge converted numbers.
- Throw ExcessivePriceException for prices greater than 1,000,000. Exactly 1,000,000 is allowed.

The model holds a supplied price for display; no money calculations are required. It protects its state even when called outside the form. Failed construction provides no new result; a rejected setter must preserve its previous property value.

Replace ProductController.php with this scaffold and adapt the messages:

```php
<?php
declare(strict_types=1);

namespace App\Exercises\Class7;

use InvalidArgumentException;

class ProductController extends Controller
{
    public function form(array $input, bool $submitted): Response
    {
        $nameInput = $input['name'] ?? '';
        $priceInput = $input['price'] ?? '';
        $name = is_string($nameInput) ? $nameInput : '';
        $priceText = is_string($priceInput) ? $priceInput : '';
        $errors = [];
        $quote = null;
        $savedId = null;
        $status = 200;
        $attemptState = 'No submission yet.';

        if ($submitted) {
            try {
                if (!is_string($nameInput)) {
                    $errors[] = 'Enter a single supply name.';
                } elseif (strlen(trim($name)) > 80) {
                    $errors[] = 'Use a name of at most 80 bytes.';
                }

                if (!is_string($priceInput)
                    || preg_match('/^-?(?:0|[1-9][0-9]*)(?:\.[0-9]{1,2})?$/D', trim($priceText)) !== 1) {
                    $errors[] = 'Enter a price such as 4.50, with no more than two decimal places.';
                }

                if ($errors === []) {
                    $quote = new Product(trim($name), (float) trim($priceText));
                }
            } catch (EmptyNameException $e) {
                $errors[] = 'Enter a supply name.';
            } catch (ExcessivePriceException $e) {
                $errors[] = 'Use a price no greater than 1,000,000.';
            } catch (InvalidArgumentException $e) {
                $errors[] = 'Use a finite price of zero or greater.';
            } finally {
                $attemptState = 'The submission attempt finished.';
            }

            if ($errors !== []) {
                $status = 422;
            }
        }

        $body = $this->twig->render('quote.html.twig', compact(
            'name', 'priceText', 'errors', 'quote', 'savedId', 'attemptState',
        ));
        return new Response($body, $status);
    }
}
```

Ordinary wrong shapes and numeric formats use conditionals. A syntactically valid negative price reaches the model's built-in InvalidArgumentException; a blank name reaches its custom exception. Specific catches precede their parent. Finally describes **an attempt ending**, not success, persistence, or rollback. Rendering stays outside this narrow handling block.

1. Implement the model and exception classes. Test through the form: valid values, blank name, -0.01, 0, 1,000,000, and 1,000,000.01. Try a very long digit string to exercise non-finite/range checks after conversion.
2. Check 01, 4.567, 1e3, +4, and empty price: format errors under this policy. Whitespace around otherwise valid input is trimmed for validation; original scalar text stays in the form. The name limit is 80 bytes, not necessarily 80 Unicode characters.
3. In browser developer tools, temporarily change a control's name to `name[]` or `price[]` and submit. Confirm a correction rather than TypeError. Restore the control afterward.
4. Temporarily reorder the parent catch before the custom catches. Observe that it intercepts their failures, then restore specific-first order. Change diagnostic message wording temporarily and verify the chosen response still depends on type; restore the wording.
5. Add a small **web-only state check**: construct a valid Product, attempt an invalid setter inside a separate try/catch/finally, and pass its before/after getter values and an attempt marker into Twig. Show that rejection preserves the old value. Keep this distinct from the submitted quote and do not save it.

Check: valid submissions produce 200 with Valid preview. Invalid submissions produce 422 with corrections and no result. Each submitted attempt shows the finally marker. Nothing is saved yet. Explain why catching did not repair the input and why statement order preserves model state.

## Exercise 7-3: Persist accepted quotes as JSON

Create `storage/exercises/class7/quotes/` outside public/. Copy and adapt this JsonQuoteStore.php. It writes a complete temporary file and publishes it under a generated .json filename after a successful write. Readers will consider only .json files.

Create `src/Exercises/Class7/JsonQuoteStore.php`:

```php
<?php
declare(strict_types=1);

namespace App\Exercises\Class7;

use RuntimeException;

class JsonQuoteStore
{
    private const DIRECTORY = __DIR__ . '/../../../storage/exercises/class7/quotes';

    private bool $cleanupFailed = false;

    public function cleanupFailed(): bool
    {
        return $this->cleanupFailed;
    }

    public function save(Product $product): string
    {
        $this->cleanupFailed = false;
        if (!is_dir(self::DIRECTORY)) {
            throw new RuntimeException('Quote storage directory is missing.');
        }

        $id = bin2hex(random_bytes(16));
        $temporaryPath = self::DIRECTORY . '/' . $id . '.tmp';
        $finalPath = self::DIRECTORY . '/' . $id . '.json';

        try {
            $json = json_encode([
                'id' => $id,
                'name' => $product->getName(),
                'price' => $product->getPrice(),
                'createdAt' => gmdate('c'),
            ], JSON_THROW_ON_ERROR | JSON_PRETTY_PRINT);

            $written = @file_put_contents($temporaryPath, $json, LOCK_EX);
            if ($written === false || $written !== strlen($json)) {
                throw new RuntimeException('Could not write the complete quote.');
            }
            if (!@rename($temporaryPath, $finalPath)) {
                throw new RuntimeException('Could not publish the quote.');
            }
            return $id;
        } finally {
            if (is_file($temporaryPath) && !@unlink($temporaryPath)) {
                $this->cleanupFailed = true;
            }
        }
    }
}
```

The targeted @ operators suppress filesystem warnings **only where a result is checked** and converted into a storage failure or cleanup flag. They do not make failure successful. Filesystem functions often warn and return false rather than automatically throwing. The byte-count check rejects an incomplete write. JSON_THROW_ON_ERROR makes an encoding failure throw JsonException.

Temporary and final paths share a directory. This avoids intentionally exposing partly written .json files, but does not promise crash-proof durability or duplicate prevention. The store does not edit existing records. LOCK_EX covers the individual write, not a shared collection update. Finally removes a leftover temporary file when possible; it does not undo a successfully published quote. A cleanup failure must not replace the original exception.

Your work:

1. Import JsonException and RuntimeException in ProductController. Initialize `$store = null` before the submitted try.
2. Replace the successful construction statement with these steps: construct a local candidate Product; create JsonQuoteStore; call save and receive its ID; **only then** assign the candidate to quote and the ID to savedId. A failed save must leave both result variables null.
3. After the known validation catches, add JsonException and RuntimeException catches with approved messages such as “We could not prepare this quote for saving” and “Quote storage is unavailable.” Set status to 500. Do not display raw messages or paths.
4. Preserve input on storage failure. Change the post-try status rule to set 422 only when there are errors **and status is still 200**, so it cannot overwrite a storage 500.
5. Keep the controller's finally attempt marker. If store is not null and cleanupFailed returns true, add a generic cleanup-attention message and keep a 500 status. Do not throw from finally. The store's own finally handles its temporary file.
6. Remove the intermediate preview branch from quote.html.twig. Show Quote saved only when savedId and quote are available. Keep the unchanged entry boundary for unexpected failures.

| Browser/editor test | Expected outcome |
|---|---|
| Valid submission | 200, Quote saved, reference ID, one new .json file |
| Blank name, negative/excessive price, malformed fields | 422, no new file, no saved result |
| Zero or exact maximum price | Saved correctly |
| Temporarily point DIRECTORY at an absent local test directory | 500 Twig failure response, input retained, no saved result |
| Restore DIRECTORY and submit again | Save succeeds |

Inspect a record in your editor: id, name, numeric price, and an ISO-style UTC createdAt string. A successful save leaves no .tmp file. No user input controls a storage path. Explain why success depends on save completing, and why the controller handles storage failure differently from invalid input.

## Exercise 7-4: Load saved quotes and handle built-in JSON failures

Add a Saved quotes page that survives a new browser request. This reader never rewrites a corrupt file or silently turns a load failure into an empty collection.

Create `src/Exercises/Class7/JsonQuoteReader.php`:

```php
<?php
declare(strict_types=1);

namespace App\Exercises\Class7;

use RuntimeException;
use UnexpectedValueException;

class JsonQuoteReader
{
    private const DIRECTORY = __DIR__ . '/../../../storage/exercises/class7/quotes';

    public function all(): array
    {
        if (!is_dir(self::DIRECTORY)) {
            throw new RuntimeException('Quote storage directory is missing.');
        }
        $paths = glob(self::DIRECTORY . '/*.json');
        if ($paths === false) {
            throw new RuntimeException('Could not list stored quotes.');
        }

        $quotes = [];
        foreach ($paths as $path) {
            $json = @file_get_contents($path);
            if ($json === false) {
                throw new RuntimeException('Could not read a stored quote.');
            }
            $record = json_decode($json, true, 512, JSON_THROW_ON_ERROR);
            if (!is_array($record)
                || !isset($record['id'], $record['name'], $record['price'], $record['createdAt'])
                || !is_string($record['id'])
                || preg_match('/^[a-f0-9]{32}$/D', $record['id']) !== 1
                || $record['id'] !== basename($path, '.json')
                || !is_string($record['name']) || trim($record['name']) === ''
                || (!is_int($record['price']) && !is_float($record['price']))
                || !is_finite((float) $record['price'])
                || $record['price'] < 0 || $record['price'] > 1000000
                || !is_string($record['createdAt']) || $record['createdAt'] === '') {
                throw new UnexpectedValueException('Stored quote has an invalid structure.');
            }
            $quotes[] = $record;
        }
        return $quotes;
    }
}
```

Malformed JSON throws JsonException. Valid JSON with wrong fields throws UnexpectedValueException. Missing storage or failed reads throw RuntimeException. UnexpectedValueException is a RuntimeException subclass, so its catch belongs first. An existing empty directory yields an empty list normally.

Your work:

1. Add `ProductController::savedQuotes(): Response`. Initialize quotes to an empty array, error to null, status to 200, and loadState to a starting message.
2. Inside try, assign JsonQuoteReader::all to quotes. Catch JsonException, then UnexpectedValueException, then RuntimeException, with distinct approved messages and 500 status. Examples: “Saved quotes contain unreadable JSON,” “A saved quote has invalid fields,” and “Saved quotes are unavailable.” Keep paths and diagnostic details private.
3. In finally, set loadState to “The load attempt finished.” Render after this block, passing quotes, error, and loadState into Twig. Return a complete Response.
4. Add `action=quotes` routing in Application and a relative Saved quotes navigation link. Missing, unknown, and array-shaped actions select the form. A POST to the form submits a new quote; Saved quotes GET navigation only reads.
5. Create quotes.html.twig extending base. On error, show the error and **do not** show an empty-state or partial-results message. Otherwise loop over quotes, showing each name, formatted price, and timestamp, with an else message for a genuinely empty collection. Display loadState separately.

The all-or-error policy is intentional. The entire right-hand-side load must finish before quotes receives the result. A broken record must not produce a misleading “no quotes” page or silently remove data.

Check in the browser/editor:

1. Save two quotes. Open Saved quotes in a new tab or refresh: both remain. GET navigation creates no new records.
2. Temporarily use an existing empty local test directory for the reader: 200 with an honest empty-state message. Restore the normal path.
3. Back up one saved .json file, then replace its content with `{broken`. Reload: 500 with the JSON-syntax response, no empty-state claim, and unchanged corrupt file. Restore the backup.
4. Temporarily change that record's price to an array using valid JSON: `"price": []`. Reload: 500 with the structure-error response, distinct from syntax failure. Restore it.
5. Temporarily point the reader at an absent local test directory: 500 with the storage response. Restore the constant. Every attempted load shows its finally marker.
6. Save markup and quotes in a name, then view the list: Twig escapes persisted values too. Data read from disk is not automatically trusted HTML.

Explain why valid JSON syntax is insufficient to trust a record, and why silently resetting essential saved data to an empty collection is the wrong recovery policy here.
