# 7.10 Class 7 comprehension check

Choose the best answer. Each question has exactly one correct answer.

## Questions

1. What does this script print?

   ```php
   <?php
   declare(strict_types=1);

   try {
       echo 'A';
       throw new Exception('Problem');
       echo 'B';
   } catch (Exception $e) {
       echo 'C';
   }
   echo 'D';
   ```

   A. ABCD.  
   B. ACD.  
   C. ACBD.  
   D. A only.  

2. A new Dessert constructor throws before assigning `$newDessert`. Separately, an existing dessert's setter rejects a negative value before assigning its calorie property. Which statement is correct?

   A. Both objects become null automatically.  
   B. Catching creates a replacement dessert with zero calories.  
   C. The existing dessert loses its previously stored value.  
   D. No new object is assigned by the failed construction, and the existing dessert retains its previous calorie value.  

3. NegativeCaloriesException extends InvalidArgumentException. Both have catch blocks for the same try. What order gives the custom type its own response?

   A. NegativeCaloriesException first, then InvalidArgumentException.  
   B. InvalidArgumentException first, then NegativeCaloriesException.  
   C. Order does not matter because both handlers always run.  
   D. Neither can be caught unless an Exception handler runs first.  

4. Why introduce ExcessiveCaloriesException instead of checking whether getMessage contains “maximum”?

   A. Custom exception classes automatically correct invalid arguments.  
   B. getMessage works only on the root Exception class.  
   C. The type identifies failure independently of diagnostic wording.  
   D. Composer chooses a catch block from message text.  

5. DessertController can redisplay a form for known bad input. Application only routes requests and has no additional recovery action. Where should the known domain exception be handled?

   A. In Dessert, which should echo the form and end the request.  
   B. In DessertController; Application can let unmatched failures propagate.  
   C. In every method on the call stack, using the same catch.  
   D. Only in Twig, after a failed object has been passed to the template.  

6. A user submits -1 calories and the controller catches NegativeCaloriesException. Which is the best response for our planner?

   A. Show a 200 success result using zero calories instead.  
   B. Retry the same constructor indefinitely until it accepts -1.  
   C. Print the complete stack trace beside a success message.  
   D. Return a 422 form with preserved scalar input, an actionable correction, and no success result.  

7. A valid dessert preview is ready, but optional notice JSON is malformed. Which policy fits our example?

   A. Invent a calorie count to replace the failed notice.  
   B. Ignore every Throwable from the whole request and always return success.  
   C. Catch JsonException in the notice helper and provide a labeled default while keeping the valid preview.  
   D. Treat the dessert as invalid even though construction succeeded.  

8. A lower layer has no safe correction or fallback, and an operation's earlier side effects may already have occurred. Which is the best decision?

   A. Let failure propagate to a layer with a handling policy; avoid automatic retry until repeating the operation is known to be safe.  
   B. Catch and discard it because a catch restores earlier state.  
   C. Retry forever because every exception is a temporary problem.  
   D. Return a successful placeholder so the caller cannot see failure.  

9. A helper acquires a stream and uses try/finally with fclose in finally. It has a pending return on success and throws on failure. When does cleanup run during these ordinary paths?

   A. Only if a matching catch appears in the helper.  
   B. Only after the caller receives the returned value.  
   C. Only on success, because exceptions skip finally.  
   D. Before the caller receives the result or handles the propagated exception; cleanup does not imply rollback.  

10. Why does the final entry boundary catch Throwable and return a generic 500 for unexpected thrown failures?

   A. Throwable catches ordinary warnings and every engine failure.  
   B. It matches both Exception and Error objects so the request ends with a controlled response; the defect still needs diagnosis and a fix.  
   C. It converts every TypeError into valid form input.  
   D. It records a private log automatically and guarantees the next request succeeds.  

## Answer key

Remove this section from the student LMS version. Award one point per correct answer, ten points total.

| Question | Answer | Teaching explanation |
|---|---|---|
| 1 | B | A prints; throw skips B; catch prints C; execution afterward prints D. |
| 2 | D | Failed construction does not assign a new result. This setter's validation before assignment preserves the old property. Catching does not repair or roll back. |
| 3 | A | PHP chooses the first matching catch; the parent would intercept its subclass. |
| 4 | C | A named type gives a stable distinction without parsing diagnostic text. |
| 5 | B | The controller has correction context. Routing alone does not justify another catch. |
| 6 | D | The correction retains useful input without pretending the operation succeeded. |
| 7 | C | The notice is optional and a safe, explicit fallback exists for that specific failure. |
| 8 | A | Propagation is appropriate when a layer cannot help. Retry requires a temporary cause, a safe repeat, and a strict limit. |
| 9 | D | Finally executes before return delivery and during exception unwinding. Cleanup does not reverse earlier effects. |
| 10 | B | Exception and Error share Throwable. The boundary controls the response but neither fixes the defect nor implements logging. |
