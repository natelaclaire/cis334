# 4.0 Class 4 overview and tutorial roadmap

Class 4 covers Chapter 20, **Managing Classes and Namespaces with Composer**, in *PHP Crash Course*. We follow its progression from names to project configuration, autoloading, and dependencies. The PHP autoload callback demonstration, interactive `composer init`, and expanded App/PSR-4 discussion are supplements. The chapter already introduces Composer autoloading and PSR-4 and shows an App namespace in a framework example.

By the end of class, you should be able to distinguish a class name from its file location, resolve namespace collisions, trace an autoload request, initialize an application package, map `App\` to `src/`, and install and use two third-party packages.

## Instructor preparation

Use PHP 8.4 and Composer 2. Open a terminal at the student's repository root. All paths below are relative to that root, **not** to this course-notes folder. Create `src/Models/`, `src/Admin/`, and `public/class4/` using the editor. Existing work can stay alongside these files. If a `composer.json` already exists, inspect and merge the new settings instead of overwriting it or rerunning init. Examples run at the CLI; they are not HTML pages.

The demonstrations are cumulative. Every full PHP file begins with `<?php` and `declare(strict_types=1);`, uses four-space indentation, and omits the closing PHP tag. Restore intentional errors before proceeding. Tutorials 4.1–4.2 use explicit requires, 4.4 uses a temporary custom loader, and 4.5 replaces it with Composer. No unpublished starter files are needed.

The final project has this shape:

```text
composer.json
composer.lock
.gitignore
.env.example
.env
src/
    Models/User.php
    Admin/User.php
public/
    class4/index.php
    class4/packages.php
vendor/
    autoload.php
```

The final `composer.json` must have `"type": "project"`, `"autoload": {"psr-4": {"App\\": "src/"}}`, and both `symfony/dotenv` and `phpmailer/phpmailer` under `require`. Tutorial 4.6 supplies a complete example. Commit `composer.json`, `composer.lock`, source files, and `.env.example`; ignore `vendor/` and the local `.env`.

See the [migration inventory](class-4-content-migration-notes.md) for chapter mapping and decisions about previous files.
