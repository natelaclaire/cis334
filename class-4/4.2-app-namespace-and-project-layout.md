# 4.2 The App namespace and project layout

`App` is a convention for an application's own code. It is not a PHP keyword, a built-in namespace, or a framework we must install. We can use it in a plain PHP project. Third-party code keeps its own namespaces.

## Walk through our files

| Responsibility | PHP class name | File in our repository |
|---|---|---|
| Application model | `App\Tutorials\Class4\User` | `src/Tutorials/Class4/Models/User.php` |
| Administration example | `App\Tutorials\Class4\Admin\User` | `src/Tutorials/Class4/Admin/User.php` |

Open each class and compare its namespace, short class name, and path. The filename includes `.php`; the class name does not. `App` corresponds to `src/` in the mapping we will configure. We will not create `src/App/Tutorials/Class4/User.php`.

At this point our explicit requires load the files. PHP itself does not infer that App means src. In 4.5, Composer will receive that rule.

Frameworks can choose different base directories. Laravel uses an App namespace for classes under its `app/` directory. Symfony projects commonly use App with `src/`. That difference is configured, not a special behavior of the word App. See [Laravel's directory structure](https://laravel.com/framework/docs/13.x/structure) and [Symfony configuration examples](https://symfony.com/doc/current/configuration.html).

## Keep three names separate

Our Composer project will be named `student/cis334-app`; our application namespace will be `App`; our class directory will be `src/`. These are three different settings. The package name does not require a `Student\Cis334App` namespace. Published libraries usually choose a distinctive vendor namespace so they can coexist with other libraries.
