# 4.7 Use Dotenv and PHPMailer

Now use an application class and two library classes through the same Composer loader. This local demonstration prepares a message without sending it or requiring an SMTP account.

## Create configuration

At the repository root, create `.env.example` with these nonsecret sample values. Copy it to `.env` using the editor:

```dotenv
APP_NAME="CIS 334 Mail Lab"
MAIL_FROM_ADDRESS="instructor@example.com"
MAIL_FROM_NAME="CIS 334"
```

Keep `.env` outside `public/` and ignored by Git. Commit `.env.example` so a classmate knows what configuration to create. A .env file is plain text, not encryption. Real deployment environment variables may supply these values instead.

## Load, construct, and prepare

Create `public/class4/packages.php`:

```php
<?php
declare(strict_types=1);

use App\Models\User;
use PHPMailer\PHPMailer\PHPMailer;
use Symfony\Component\Dotenv\Dotenv;

require_once __DIR__ . '/../../vendor/autoload.php';

$dotenv = new Dotenv();
$dotenv->load(__DIR__ . '/../../.env');

$user = new User('Avery');
$mail = new PHPMailer(true);
$mail->CharSet = 'UTF-8';
$mail->setFrom($_ENV['MAIL_FROM_ADDRESS'], $_ENV['MAIL_FROM_NAME']);
$mail->addAddress('student@example.com', $user->getName());
$mail->Subject = $_ENV['APP_NAME'] . ': welcome';
$mail->Body = 'Hello ' . $user->getName() . '!';

if ($mail->preSend()) {
    echo 'Prepared: ', $mail->Subject, PHP_EOL;
    echo 'Body: ', $mail->Body, PHP_EOL;
}
```

Run:

```bash
php public/class4/packages.php
```

With the sample values and no preexisting environment overrides, expect:

```text
Prepared: CIS 334 Mail Lab: welcome
Body: Hello Avery!
```

`Dotenv::load()` reads the supplied file and makes values available through `$_ENV` and `$_SERVER`; existing environment values take precedence by default. It does not imply that `getenv()` will be populated. Missing `.env` is a setup error for this particular script: copy the example first.

`new PHPMailer(true)` enables exceptions for mailer errors. `preSend()` assembles the message locally; `send()` would attempt delivery. We do not call send here. SMTP configuration and exception-handling design can be covered later. If the demonstration throws, verify the sample addresses and configuration rather than trying a live mail server.

## Trace the three classes

Ask students to point out each class's package or directory. App's User is ours, Dotenv is installed under vendor, and PHPMailer is another installed package. All three imports select names; the shared bootstrap handles loading. Package installation does not automatically read `.env` or construct a mailer: our program explicitly performs those operations.

Add `"packages": "@php public/class4/packages.php"` to the existing `scripts` object, including the needed comma, and run `composer packages`. Finish with `composer validate` and review the requirements listed in the overview.

References: [Symfony Dotenv](https://github.com/symfony/dotenv), [Symfony environment configuration](https://symfony.com/doc/current/configuration.html#configuring-environment-variables-in-env-files), and [PHPMailer documentation and source](https://github.com/PHPMailer/PHPMailer).
