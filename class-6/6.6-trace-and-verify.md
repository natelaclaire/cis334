# 6.6 Trace and verify the application

Use the completed application from 6.5. This tutorial adds no files. Trace the program and verify that each responsibility has a clear home.

## Follow a Products request

1. The browser requests `/tutorials/class6/index.php?action=products`.
2. index.php loads the existing Composer autoloader, creates Application, and calls run.
3. run constructs the page controllers. Each inherits Controller's Twig initialization.
4. Application reads action and the products case calls ProductController::productList.
5. productList creates Product objects and passes them in the products context entry to Twig.
6. Twig renders products.html.twig with the layout from base.html.twig. The controller echoes the returned HTML string.
7. The browser displays the HTML and requests style.css through its relative URL.

The request passes through the entry script, front controller, page controller, and view. Controller is involved through inherited initialization; it is not another route or an object we construct directly.

## Match responsibilities to files

| Responsibility | Owner |
|---|---|
| Load Composer and start the application | public/tutorials/class6/index.php |
| Read action and choose a known page method | Application |
| Initialize Twig for each page controller | Abstract Controller |
| Prepare Home or Contact | DefaultController |
| Prepare the product collection and render its page | ProductController |
| Represent one product's data | Product |
| Define shared markup and page-specific presentation | Base and child Twig templates |

## Complete the browser checkpoint

| Request suffix | Expected result |
|---|---|
| No query string | Home |
| `?action=home` | Home |
| `?action=contact` | Contact |
| `?action=products` | Products and three name/price pairs |
| `?action=unknown` | Home fallback |
| `?action[]=products` | Home fallback without a type warning |

On each page, check its tab title, heading, shared navigation, and active link. Confirm the response contains one document rather than concatenated pages. Repeat the temporary empty-array check, then restore the product data.

## Rehearse adding a feature

For another basic page, plan a public DefaultController method, a child template, an explicit Application case, and a link in base. For another family of pages, plan a specialized Controller subclass and the data class it needs. The reinforcement exercises put both approaches into practice.

Ask students to explain these mistakes before fixing them: putting the switch in a Twig template, creating Product objects in Application, making a page method private, or copying Twig initialization into every new subclass. Each either mixes responsibilities or breaks the intended access and inheritance rules.

Finish by opening the [reinforcement exercises](6.9-class-6-reinforcement-exercises.md). Build those in the separate exercise namespace and folders so both sites can run independently.
