# 6.11 Class 6 comprehension check

Choose the best answer. Each question has exactly one correct answer.

## Questions

1. What is Application responsible for after the separation in 6.2?

   A. Writing the product-list HTML.  
   B. Reading the action and choosing a page-controller method.  
   C. Storing each product name and price.  
   D. Providing the shared Twig layout.  

2. Why must DefaultController::contact be public?

   A. Twig requires every PHP method to be public.  
   B. Public methods automatically become URL routes.  
   C. Composer can load only public methods.  
   D. Application calls it from outside DefaultController.  

3. Which class should create the sample Product objects and prepare their template context?

   A. ProductController.  
   B. Application.  
   C. The Composer autoloader.  
   D. The base Twig template.  

4. Given `$args = ['products' => $products];`, what supplies the products variable inside the Twig view?

   A. The PHP filename Product.php.  
   B. The action query parameter by itself.  
   C. The products key passed in the render context.  
   D. The name of the Controller superclass.  

5. What happens when the products array is empty in our product view?

   A. The for loop's else branch displays the empty-state message.  
   B. Application automatically redirects to Contact.  
   C. Twig creates a default Product object.  
   D. The parent constructor stops running.  

6. Why declare Controller abstract?

   A. To make all its members private.  
   B. To force each child to duplicate its constructor.  
   C. To make it the application entry script.  
   D. To prevent direct instantiation while supplying shared behavior to subclasses.  

7. Why is the shared twig property protected?

   A. So any code can replace it directly.  
   B. So methods in controller subclasses can use it without exposing it publicly.  
   C. So Application can call it as a route.  
   D. So Twig templates become PHP subclasses.  

8. ProductController extends Controller and declares no constructor. What initializes its Twig environment?

   A. Application must assign the property directly.  
   B. The products Twig template initializes it.  
   C. The inherited Controller constructor runs when the object is created.  
   D. Composer copies the DefaultController object.  

9. What is the difference between PHP controller inheritance and Twig template inheritance here?

   A. PHP shares controller setup; Twig shares layout and blocks.  
   B. Both declarations create URL routes.  
   C. Twig inheritance replaces Composer autoloading.  
   D. PHP inheritance automatically chooses an active navigation link.  

10. What happens for `?action=unknown` in our completed tutorial application?

   A. The query value is used as a template filename.  
   B. Composer creates UnknownController.  
   C. Twig renders every child template.  
   D. The switch default delegates to DefaultController::home.  

## Answer key and teaching notes

1. **B.** Application makes the routing decision and delegates page generation. Review 6.2.
2. **D.** External calls require public access; the explicit switch still defines routing. Review 6.2.
3. **A.** ProductController prepares the product page; Product represents one item. Review 6.3.
4. **C.** Context keys provide the template variable names. Review 6.3–6.4.
5. **A.** Twig for/else handles a collection with no items. Review 6.4.
6. **D.** Concrete page controllers inherit its implemented initialization. Review 6.5.
7. **B.** Protected access supports the controller hierarchy without public property access. Review 6.5.
8. **C.** A child without its own constructor inherits the parent constructor. Review 6.5.
9. **A.** The two inheritance mechanisms operate in different layers. Review 6.5–6.6.
10. **D.** The explicitly programmed Home fallback remains after refactoring. Review 6.6.

Suggested scoring: 9–10 ready to continue; 7–8 review missed sections; 0–6 repeat the relevant demonstrations and exercises. Omit this answer key when importing the student-facing quiz into the LMS.
