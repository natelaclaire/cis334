# 6.9 Class 6 reinforcement exercises

This week's exercises reinforce the chapter's architecture and its separation of routing and display, but it's an opportunity to get a little more creative. You'll build a Web site for yourself. You are welcome to use much of the code from the tutorials or to start fresh - I'll be looking for your unique touch and to see that you can apply the concepts in a new context.

All exercises use `public/exercises/class6/index.php`, classes in `src/Exercises/Class6/` with namespace `App\Exercises\Class6`, and templates in `templates/exercises/class6/`. The entry script uses `__DIR__ . '/../../../vendor/autoload.php'`. The controller's template path is `__DIR__ . '/../../../templates/exercises/class6'`.

Use strict types, typed properties and return values, matching filenames, and four-space indentation. Run the existing server and open `/exercises/class6/index.php`. Use relative index.php links. No databases or sessions are needed.

## Exercise 6-1: Build a fresh two-page baseline

1. Create the entry script (`public/exercises/class6/index.php`) to load Composer, instantiate the exercise Application, and call run.
2. Create Application (`src/Exercises/Class6/Application.php`) with Twig initialization, a run method that reads action, and two routes that render their respective views. Missing, unknown, and non-string actions must select Home.
3. Create base.html.twig with one HTML document, shared navigation pointing to your two pages, pageTitle and main blocks, and an h1 that repeats pageTitle using block(). Give each navigation link a block for its active class and include a small style rule that makes active links bold.
4. Create the two Twig templates as children of base. Override the appropriate active-link block in each child.
5. Enable HTML autoescaping and strict variables when constructing Twig.

## Exercise 6-2: Separate the front controller from display

1. Create DefaultController and put Twig initialization, and the page methods there.
2. Make its page methods public so Application can call them.
3. Replace Application's rendering logic with a run method that creates DefaultController and delegates through the action switch. Remove the former Twig setup and page methods from Application.
4. Keep the entry script and templates unchanged.

Check: all requests from Exercise 6-1 produce the same visible results. Application contains no Twig rendering or HTML; DefaultController does not read the action parameter.

## Exercise 6-3: Extract and verify the shared superclass

1. Create an abstract Controller containing the template-path constant, protected Twig environment property, and public constructor that initializes Twig.
2. Make DefaultController extend Controller. Remove their repeated setup, including their constructors. Keep all their page methods public.
3. Recheck all of the routes to ensure that they work correctly with the new controller structure.

Check: the refactoring preserves the site's output; Twig setup exists only in Controller.

## Exercise 6-4: Add a data-driven page

Do you have a hobby? Something you collect, a sport you play, or a subject you study? Build a page that shows a list of objects related to your hobby. For example, if you collect coins, show a list of coin objects with name and year properties. If you play chess, show a list of game objects with game stats. If you study birds, show a list of bird objects with species and wingspan properties.

1. Create a new page with a new route, controller method (either in the DefaultController or a new controller - your choice), and template. The page should display a list of objects with at least two public properties. Use a for loop in the template to produce a table, ordered list, unordered list, or definition list. Include an else branch that shows an empty-state message. Create a custom class for the objects, with a constructor that initializes the properties and validates them. Use at least one property with a type other than string.
2. Add a link to the new page in the shared navigation and give it an active-link block. Override that block in the new page's template.

Check: The new page opens through navigation and a direct URL. The existing pages still work, all three pages show the new link, and only the current page's link is active.

## Exercise 6-5: Add a VCF download route

The [vCard 3.0 format](https://en.wikipedia.org/wiki/VCard#vCard_3.0) is a simple text format for contact information. It can be imported into many address books and email clients. You will create a route that downloads a vCard file with your contact information (or placeholders). Among other things, this exercise reinforces that Twig templates can produce any text format, not just HTML.

1. Create a new controller called VCFController that extends the base Controller.
2. Add a method to the VCFController called download() that renders `vcard.vcf.twig` and stores it in a string called `$vcardContent`, passing an array of your contact details as the context for the render() method, such as (name and email is enough, but you can add more if you want):

```php
$vcardContent = $this->twig->render('vcard.vcf.twig', [
    'firstname' => 'Jane',
    'lastname'  => 'Doe',
    'company'   => 'Acme Corp',
    'job_title' => 'Lead Developer',
    'email'     => 'jane.doe@example.com',
    'phone'     => '+15551234567',
    'website'   => 'https://example.com'
]);
```

3. Before echoing the rendered vCard, set the following HTTP headers:

```php
header('Content-Type: text/vcard; charset=utf-8');
header('Content-Disposition: attachment; filename="contact.vcf"');
header('Content-Length: ' . strlen($vcardContent));
```

4. Once that is done, echo the `$vcardContent` to send it to the browser.

5. Create a Twig template called `vcard.vcf.twig` (remember the filename needs to match the render method call) that outputs the vCard format. It should not extend any other template. Use the contact details passed in the context to fill in the appropriate fields. Use the following template as a starting point and feel free to remove or add fields as you see fit (note that the `REV` field uses Twig's date filter to generate a timestamp):

```twig
BEGIN:VCARD
VERSION:3.0
N:{{ lastname }};{{ firstname }};;;
FN:{{ firstname }} {{ lastname }}
ORG:{{ company }}
TITLE:{{ job_title }}
EMAIL;TYPE=PREF,INTERNET:{{ email }}
TEL;TYPE=CELL,VOICE:{{ phone }}
URL:{{ website }}
REV:{{ "now"|date("Ymd\\THis\\Z") }}
END:VCARD
```

6. Add a new route to Application that calls the VCFController's `download()` method. The route should be accessible through a navigation link and a direct URL. The link should not be active when on the other pages.

Check: Reload any page on your site and confirm that the new link is present. Click the link and confirm that a file download dialog appears with the filename `contact.vcf`. Open the downloaded file in any text editor and confirm that it contains your contact information in the vCard format. Note that after downloading the file, the browser should not display any HTML content (you'll remain on the current page), and the other pages should still work as expected.
