# 2.1 Thinking in Classes and Objects

Chapter 17 introduces a new way to organize familiar PHP ideas. A property is a variable attached to an object, and a method is a function attached to an object. OOP groups related data and behavior into classes so that the code resembles the problem it solves.

## Classes, objects, and messages

A **class** is a reusable description or blueprint. An **object** is one particular instance created from that class. If `Member` is a class, `$nora` and `$sam` can be two objects with different property values but the same available methods.

```php
<?php

declare(strict_types=1);

$nora = new Member();
$sam = new Member();

$nora->setDisplayName('Nora');
$sam->setDisplayName('Sam');

echo $nora->getDisplayName();
```

The expression `$nora->getDisplayName()` sends a **message** to the object by invoking one of its methods. PHP uses `->` to access an object's members. Do not confuse it with `=>`, which separates keys and values in arrays.

## Model responsibilities, not just nouns

Finding nouns in a problem description is a useful start, but a good class also has a clear responsibility:

| Class | Knows (properties) | Does (methods) |
|---|---|---|
| `Member` | display name, email | validate profile changes, create a label |
| `Post` | author, body, publication time | publish, summarize, format for display |

Avoid making one giant class responsible for everything. Ask, “Which object has the information needed to do this job?” Put the method there.

## Relationships between objects

Properties can contain objects as well as strings and numbers. A `Post` can hold a reference to the `Member` who wrote it:

```php
class Member
{
    public string $displayName;
}

class Post
{
    public Member $author;
    public string $body;
}

$author = new Member();
$author->displayName = 'Nora';

$post = new Post();
$post->author = $author;
$post->body = 'My first post';

echo $post->author->displayName;
```

This is an object relationship: the post **has an** author. The type declaration `Member $author` prevents unrelated values from being assigned.

## Encapsulation and information hiding

**Encapsulation** groups an object's state and behavior inside its class. **Information hiding** limits which code may access that state. If any code could assign `-10` to an account balance or an empty string to a required name, the object could become invalid.

A class therefore exposes a small public interface while keeping implementation details private. The rest of the application should care about what the object promises to do, not how it stores every value.

## A preview of inheritance and overriding

Chapter 17 also introduces an **is-a** relationship. A `Student` is a specialized `Member`, so it might inherit shared properties and methods:

```php
class Member
{
    public function roleLabel(): string
    {
        return 'Community member';
    }
}

class Student extends Member
{
    public function roleLabel(): string
    {
        return 'Student';
    }
}
```

`Student` **overrides** `roleLabel()` by supplying more specific behavior. For now, recognize superclass, subclass, inheritance, and overriding. We will implement inheritance in depth with Chapter 19.

## Object-oriented flow of control

OOP does not eliminate sequential execution. A small `public/index.php` remains an entry point; it loads a class, creates the main object, and calls a method:

```php
<?php

declare(strict_types=1);

require_once __DIR__ . '/../src/WebApplication.php';

$app = new WebApplication();
$app->run();
```

Control then moves into `run()` and into other objects that it creates or calls. The entry point answers “where does execution begin?” while the class design answers “which object is responsible for each job?”

## Instructor demonstration

1. Ask students to name objects in a familiar system, such as Brightspace or a library.
2. Choose two and list what each object knows and does.
3. Draw one **has-a** relationship and one possible **is-a** relationship.
4. Trace the four executable lines in the entry-point example.
5. Emphasize that inheritance is only a preview today; composition through object properties is often the simpler relationship.

## Check your understanding

Explain why `$post->author` represents a relationship, while `Student extends Member` represents a different kind of relationship. Which phrase—“has a” or “is a”—describes each?
