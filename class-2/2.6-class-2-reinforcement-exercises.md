# 2.6 Class 2 Reinforcement Exercises

Complete the exercises in order. Use PHP 8.4, `declare(strict_types=1);`, PSR-12 formatting, typed properties and methods, and one class per file unless an exercise says otherwise.

## Exercise 2-1: Model a campus activity feed

Design before coding.

1. Identify at least three classes for a campus activity feed.
2. For each class, list two or more properties and two or more methods.
3. Draw or describe at least two **has-a** relationships.
4. Identify one property that should not be changed directly and explain the rule the class must enforce.
5. Sketch an entry point that creates the main object and sends it a message to run.

**Deliverable:** `exercise-2-1.md` containing the model, responsibilities, relationships, and entry-point sketch.

## Exercise 2-2: Declare collaborating objects

Create `Member.php`, `Post.php`, and `index.php`.

1. Give `Member` private typed properties for `displayName` and `email`.
2. Give `Post` private typed properties for a `Member` author and string body.
3. Write public getters and setters. Trim names and post bodies, reject empty values, and validate email with `filter_var()`.
4. Add constructors that produce valid objects immediately and reuse the validation logic.
5. Instantiate two members and three posts, then display each post with its author's name.

**Success check:** no calling code directly accesses a private property, and invalid values throw `InvalidArgumentException`.

## Exercise 2-3: Refactor accessors to PHP 8.4 property hooks

Make a copy of Exercise 2-2 and refactor the `Member` class.

1. Replace the display-name getter and setter with a public backed property whose `set` hook trims and rejects an empty name.
2. Replace the email getter and setter with a backed property whose `set` hook validates the address.
3. Add a virtual, get-only `initials` property computed from the display name.
4. Add a publicly readable, `private(set)` integer ID. Assign it inside the class and demonstrate that outside code cannot replace it.
5. Update calling code to use property syntax and comment out one deliberately invalid assignment after observing the error.

**Success check:** `$member->initials` is computed rather than stored, and the class contains no routine `getDisplayName()` or `setDisplayName()` methods.

## Exercise 2-4: Add useful object behavior

Extend your `Post` class without using inheritance.

1. Add a constructor that requires an author and body and optionally accepts a publication date.
2. Use constructor property promotion only where no validation is needed; be prepared to explain the choice.
3. Implement `__toString()` to return a short plain-text representation.
4. Add `excerpt(int $maximumLength): string`. It must reject a maximum below 1 and shorten long text without changing the stored body.
5. Add a virtual or method-based `isPublished` value calculated from the publication date.

**Success check:** echoing a post works, and changing its body causes the next excerpt to reflect the new body.

## Exercise 2-5: Trace identity and handle absence

Write a short script that uses your member objects.

1. Assign one `Member` object to two variables.
2. Change the object through the second variable and prove that the first sees the change.
3. Use `===` to prove both variables identify the same object.
4. Write `findMember(array $members, int $id): ?Member`.
5. Demonstrate one successful lookup and one missing lookup.
6. Handle one missing result with an explicit `if`, and another with `?->` and `??`.
7. In a comment, explain why object assignment did not make an independent copy.

**Success check:** the script produces no attempt-to-read-property-on-null warning or error.

## Submission checklist

* All five exercises are complete.
* PHP files pass `php -l`.
* Invalid states are rejected at the object's public boundary.
* Each class has one clear responsibility.
* Output is escaped with `htmlspecialchars()` if any exercise renders user-controlled text as HTML.
