# 2.3 Encapsulation, Accessors, and Property Hooks

Chapter 18 protects properties with traditional accessor and mutator methods. PHP 8.4 adds property hooks, a modern way to keep property syntax while controlling reads and writes. Learn the traditional form first because it is common in existing PHP and makes the boundary explicit.

## Getters and setters

An **accessor** (getter) returns a value. A **mutator** (setter) changes a value. They let the object screen data before it enters its state.

```php
class Product
{
    private string $name;
    private float $price;

    public function getName(): string
    {
        return $this->name;
    }

    public function setName(string $name): void
    {
        $name = trim($name);

        if ($name === '') {
            throw new InvalidArgumentException('Name cannot be empty.');
        }

        $this->name = $name;
    }

    public function getPrice(): float
    {
        return $this->price;
    }

    public function setPrice(float $price): void
    {
        if ($price < 0) {
            throw new InvalidArgumentException('Price cannot be negative.');
        }

        $this->price = $price;
    }
}
```

The setter establishes an invariant: a valid `Product` never has an empty name or negative price. Throwing an exception makes invalid input visible; silently ignoring it leaves calling code unsure whether the update worked.

Not every property needs both methods. Omit a setter when outside code should not replace a value, and omit a getter when the stored representation is an implementation detail.

## PHP 8.4 property hooks

A property hook intercepts a read (`get`) or write (`set`) while callers use ordinary property syntax. This removes boilerplate without giving up validation.

```php
class Product
{
    public string $name {
        set {
            $value = trim($value);

            if ($value === '') {
                throw new InvalidArgumentException('Name cannot be empty.');
            }

            $this->name = $value;
        }
    }

    public float $price {
        set {
            if ($value < 0) {
                throw new InvalidArgumentException('Price cannot be negative.');
            }

            $this->price = $value;
        }
    }
}

$hammer = new Product();
$hammer->name = '  Hammer  ';
$hammer->price = 9.99;

echo $hammer->name; // Hammer
```

These are **backed properties** because their hooks read or write the property itself. PHP recognizes that access inside the hook refers to backing storage rather than recursively calling the hook.

## Virtual properties

A hook can compute a value that is not stored:

```php
class Rectangle
{
    public float $area {
        get => $this->width * $this->height;
    }

    public function __construct(
        public float $width,
        public float $height,
    ) {
    }
}
```

`area` is virtual: `$rectangle->area` calculates from two stored properties. Because it has no `set` hook, outside code cannot assign to it.

## Asymmetric property visibility

Hooks control **what happens** during access. Asymmetric visibility controls **who may write**. PHP 8.4 allows a property to be publicly readable but more narrowly writable:

```php
class Order
{
    public private(set) string $status = 'new';

    public function submit(): void
    {
        $this->status = 'submitted';
    }
}

$order = new Order();
echo $order->status;          // allowed
// $order->status = 'paid';   // error: private(set)
```

Use a method such as `submit()` when a change represents a domain action. Use a `set` hook for property-like validation or normalization. Use asymmetric visibility when reading may be public but writing must stay inside the class or inheritance hierarchy.

Property hooks cannot be combined with `readonly` properties. Property hooks apply to non-static properties in PHP 8.4.

For the complete language rules and additional examples, see the PHP manual pages for [property hooks](https://www.php.net/manual/en/language.oop5.property-hooks.php) and [asymmetric property visibility](https://www.php.net/manual/en/language.oop5.visibility.php#language.oop5.visibility-members-asymmetric).
